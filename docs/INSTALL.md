# 安装、切换、更新与卸载

## 本地安装

1. 确认 DSH 版本为 **0.2.1-rc.2**。源码目录可运行 `node scripts/preflight.cjs "D:/dsh"` 只读检查安装包版本和布局签名；此脚本不修改 DSH。
2. 在 DSH「插件」页关闭正在使用的外观皮肤，例如 `@smalltailqwq/dsh-client-ui-skin-maid-atelier`，然后重启。这只是停用皮肤，不要卸载 DSH 的 sidebar、conversation、workspace、settings、ui-renderer 等原生功能插件。
3. 将交付的 `dsh-control-room-0.1.9.tgz` 放到固定目录。在 DSH 左侧「插件」→ 安装插件的包输入框中粘贴这个 **文件的绝对路径**。DSH 安装器支持本地 tarball spec；不要把整个源码 ZIP 当成安装包。
4. 核对显示名称为 **发射控制室 / Mission Control Room**（包名 `dsh-control-room`）、版本为 `0.1.9` 后安装并启用。安装器若提示重启，重启 DSH。不要用普通 Web CLI 强行修改 desktop profile，它由 Electron 应用管理。
5. 打开现有会话或新建测试会话，先检查侧栏、输入、模型选择、附件、工具审批、右侧文件／浏览器／终端与设置。再执行一个无副作用的小任务，核对四个 HUD 圆环、任务名及原生停止／插话行为。

建议先在独立试验 profile 使用；如果通过桌面 profile 试用，保留此前皮肤的已安装包以便回退。不要同时启用两套全局皮肤。安装器通常会自行复制或缓存包，但更新前请保留交付 tarball。

## 非 desktop profile 的 CLI

macOS/npm 构建的自动生成类名可以不同，0.1.9 不要求它们与 Windows 一致。兼容性只读检查还可传入 `/Applications/应用名称.app`、`/完整路径/app.asar` 或 npm 安装对应的 `/完整路径/node_modules`。此检查只确认已知结构与服务签名，不代替真实 Mac 安装验证。

已配置 DSH CLI 时，使用 DSH 自有的包管理命令，例如：

```powershell
dsh plugin --profile web add 'C:/完整目录/dsh-control-room-0.1.9.tgz'
```

以上仅用于自己的 Web 试验 profile，不能据此推断 desktop 也能由普通 CLI 管理。CLI 可能通过包管理器核查 profile 中其他依赖，离线网络是否足够取决于现有缓存；本主题自身不含新增运行依赖或安装脚本。

## 暂时停用与卸载

在 DSH「插件」页停用 **发射控制室 / dsh-control-room** 组合包，按提示重启。主题的样式、叠加层、计时器、监听器和订阅随卸载释放，原生界面恢复；若无 HMR，必须重启后才停止旧代码。

确认已恢复后，可在同一插件页移除组合包，再重新启用原来的皮肤。不要删除会话、工作区、账号设置或整个 `.dsh` 目录。本主题没有自己的会话数据库，无需迁移聊天记录。

## 更新

先关闭本主题，保留旧 tarball 和对应版本说明，再通过 DSH 插件管理器移除旧包并安装新包。正在使用且不能移除的启动包，先关闭并重启再处理。安装失败时保留 DSH 的原始错误信息；不要复制代码覆盖 app.asar。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 安装后没变化 | 确认组合包已启用、不是只安装未选择；重启；检查其他皮肤是否仍启用 |
| 0.1.0 只有黑色侧栏，背景与 HUD 不出现 | 更新到 0.1.9 并重启；旧版未适配 main 插槽包装层，不必删除聊天或重新配置账号 |
| Mac/npm/Web 构建上旧版主题不出现 | 更新到 0.1.9；旧版写死 Windows 构建类名，单纯重启不能修复类名不匹配 |
| 版本不匹配 | 停止安装，提供版本信息进行重新适配 |
| 原生界面受挤压 | 窄窗口会自动隐藏人物；缩回右侧面板或扩大窗口；需要时停用主题恢复原布局 |
| Token 或速度是「—」 | 用量依赖 tokenUsage；速度优先取 sessionStats，缺失时需要已保存回复中的输出 Token 和真实首 Token 时间。步骤切换不再清空已有速度；无有效测量或断线时仍显示未知 |
| 找不到 END TASK 圆环 | 0.1.9 已改为只读 CONTEXT；停止操作恢复为输入框内的原生停止按钮 |
| CONTEXT 是「—」 | 尚无 contextPressure 分子或 contextWindow 容量；等待提供方报告，缺失时不伪造 |
| 停止失败／超时 | 核对 DSH 原生停止与会话状态；主题不另行发送取消请求 |
| 主题互相覆盖 | 只启用一套外观皮肤，然后重启 |

交付方没有自动安装到你的真实 profile，也没有执行任何真实模型任务。

## 运行中插话与排队

本主题使用 DSH 原生发送流程。任务运行且输入普通消息后，按钮会明确显示「排队发送」或「插话发送」；没有草稿时仍显示原生停止按钮，任务结束后为普通发送。

在 **设置 → 通用 → 繁忙时的发送行为 → 插话发送** 中可让 Enter 和发送按钮采用插话。默认「排队发送」时，**Mac 用 Cmd+Enter，Windows 用 Ctrl+Enter** 执行另一种发送方式；若已设为插话，该快捷键改为排队。附件上传、命令、子会话和发送窗口限制仍遵循 DSH；插话窗口关闭时宿主可能改为排队。主题没有绕过这些规则，也没有另建一套消息队列。

## 0.1.9 界面变化

完整任务名显示在计时下方；左上角当前任务名与输入下方统计隐藏。输入框保留原生停止。原结束圆环改为上下文占用。用量、速度满环提高为 1 亿 Token 和 1000 Token/s。角色采用轻微呼吸浮动，系统减少动态效果时静止。

## 0.1.9 速度修复

采用与 DSH 原生统计栏相同的会话平均生成速度，按已结算输出 Token 与解码时间计算。换步骤、执行工具和重新读取部分历史时不会仅因缺少临时 live-chunk 而丢失读数。原生统计源可选，缺失时回退真实已保存回复计时；完全缺失时显示「—」，不使用字符数估算。更新后必须重启 DSH。
